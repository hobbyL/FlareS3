# /shares P1 即将过期治理快捷预设设计

**目标**

在已补齐“已过期治理”入口后，再为 `/shares` 增加一条与之配套的最小治理预设：一键切到“即将过期分享处理视图”，方便用户优先处理仍有效但已有明确到期时间的分享。

本轮只补一个快捷入口：

- 顶部新增“即将过期治理”按钮

## 本轮确认范围

**包含：**

- `/shares` 顶部新增一个快捷治理按钮
- 通过前端预设一次性修改现有筛选状态：
  - `status = active`
  - `sort_key = expires_at__asc`
  - 清空 `expires_from_date / expires_to_date`
- 点击按钮后立即请求列表
- 保留当前：
  - `q`
  - `type`
  - `owner_id`
- 前端补最小纯函数测试与页面验证

**不包含：**

- 新增后端接口或新的排序字段
- 自动限定“未来 7 天”之类的固定时间范围
- 预设持久化
- 自动批量关闭

## 方案对比

### 方案 A：新增一个“即将过期治理”快捷按钮（推荐）

点击后直接把当前列表切到：

- `active`
- `expires_at__asc`

并清空过期范围。

**优点：**

- 和“已过期治理”形成一对
- 完全复用现有筛选与排序系统
- 不需要改 worker

**缺点：**

- “即将过期”没有硬性的时间窗口，只表示“按最早到期的有效分享优先看”

### 方案 B：自动套用未来 N 天时间范围

例如自动设置未来 7 天。

**优点：**

- 更严格贴近“即将过期”直觉

**缺点：**

- 需要引入日期计算和边界说明
- 用户对 N 天预期可能不一致
- 超出本轮最小范围

### 方案 C：做统一快捷预设下拉

**优点：**

- 后续扩展性更强

**缺点：**

- 当前只有两个高价值预设，按钮更直接
- 会引入额外状态管理复杂度

**结论：采用方案 A。**

## 详细设计

### 1. 交互位置

在 `frontend/src/views/Shares.vue` 顶部操作区，把它放在“已过期治理”旁边，形成一组治理按钮。

### 2. 预设行为

点击按钮时：

- 保留：
  - `q`
  - `type`
  - `owner_id`
- 覆盖：
  - `status = active`
  - `sort_key = expires_at__asc`
- 清空：
  - `expires_from_date`
  - `expires_to_date`
- 重置：
  - `page = 1`
- 然后立即执行列表请求

### 3. 为什么使用 `active + expires_at__asc`

本轮对“即将过期治理”的定义是：

- 只看当前仍有效的分享
- 在这些记录里按最早到期优先排序

这样用户能先看到最需要处理的有效分享。

### 4. 与现有筛选的关系

它不是全量重置，只接管治理强相关字段：

- 状态
- 排序
- 过期范围

而保留上下文筛选：

- 搜索词
- 类型
- 所属用户

### 5. 实现边界

本轮只做前端：

- 不增加 worker 参数
- 不增加新的列表协议
- 不增加新的 sort key

建议继续把预设逻辑下沉到 `frontend/src/utils/shares.js`，保持 `Shares.vue` 只负责编排。

### 6. 测试策略

在 `frontend/tests/shares-utils.test.js` 中补充：

- 一个纯函数，负责生成“即将过期治理”预设后的 filters
- 断言它会：
  - 保留 `q/type/owner_id`
  - 强制 `status=active`
  - 强制 `sort_key=expires_at__asc`
  - 清空过期范围

页面层继续通过：

- `lint`
- `build`

验证不回归。

## 风险与控制

### 风险 1：用户把“即将过期”理解成未来固定几天

**控制：** 本轮明确采用最小定义：有效分享中按过期时间升序查看，不增加固定窗口。

### 风险 2：无过期时间的有效分享混在治理视图里

**控制：** 现有排序已保证 `expires_at = null` 尾排，因此仍可先看到有明确到期时间的记录。

### 风险 3：和已过期治理按钮语义混淆

**控制：** 两个按钮分别绑定不同状态：

- `expired`
- `active`

但都统一使用 `expires_at__asc` 方便理解。

## 验收标准

- `/shares` 顶部可一键进入“即将过期治理”视图
- 点击后列表立即刷新
- 视图应用：
  - `status = active`
  - `sort_key = expires_at__asc`
  - 清空过期范围
- 当前 `q/type/owner_id` 保留
- 与“已过期治理”可并存且互不冲突
- 现有搜索、刷新、批量关闭、排序、过期范围筛选不回归
