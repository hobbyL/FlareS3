# /shares P1 搜索与关键操作确认设计

**目标**

在不扩大 `/shares` 第一版范围的前提下，优先补齐两项高频可用性能力：

1. 关键词搜索
2. 关键危险操作二次确认

这样站长和普通用户都能更快找到目标分享，并降低误关闭、误重生成导致的操作风险。

## 本轮确认范围

**包含：**

- 为 `GET /api/shares` 新增关键词参数 `q`
- `/shares` 页面新增关键词输入框
- 服务端搜索，保证与分页结果一致
- 为以下操作新增二次确认：
  - 关闭分享
  - 重新生成一次性文档分享

**不包含：**

- 管理员 owner 下拉可搜索
- 批量操作
- 搜索条件记忆
- 时间范围筛选
- 状态说明增强
- 分享详情抽屉

## 方案对比

### 方案 A：服务端 `q` 搜索 + 页面内统一确认弹窗

**优点：**

- 搜索结果与分页、权限边界保持一致
- 复用现有 `Modal` 交互模式，前端风格统一
- 改动集中在 `/shares` 相关代码，风险低

**缺点：**

- 需要补后端筛选逻辑和回归测试

### 方案 B：仅前端当前页本地过滤

**优点：**

- 实现更快

**缺点：**

- 只能过滤当前页
- 与后端分页不一致，站长容易误判“记录不存在”

### 方案 C：把 owner 搜索下拉一起做

**优点：**

- 管理员检索体验更完整

**缺点：**

- 现有 `Select` 组件不支持搜索，需要额外扩展组件能力
- 会把本轮从低风险体验优化扩成组件级功能升级

**结论：采用方案 A。**

## 详细设计

### 1. 后端接口扩展

扩展现有 `GET /api/shares`，新增查询参数：

- `q`：关键词

保留现有参数：

- `page`
- `limit`
- `type`
- `status`
- `owner_id`

`worker/src/routes/shares.ts` 只负责解析参数并透传到 service，不引入新的路由或新的权限中间件。

### 2. 搜索语义

搜索在 `worker/src/services/shares.ts` 聚合后的统一记录上执行，保持 KISS，不在本轮把逻辑下沉为复杂 SQL 条件拼装。

#### 普通用户匹配字段

- `resource_name`
- `share_code`

#### 管理员额外匹配字段

- `owner_username`
- `owner_id`

#### 匹配规则

- 对查询词做 `trim`
- 空字符串视为无搜索条件
- 使用大小写不敏感的包含匹配

#### 推荐过滤顺序

1. 权限过滤
2. `owner_id` 过滤（仅管理员）
3. `q` 搜索
4. `type`
5. `status`
6. `updated_at DESC` 排序
7. `page/limit` 分页

这样能保证语义清晰，也与当前 service 结构最接近。

### 3. 前端筛选区调整

在 `frontend/src/views/Shares.vue` 顶部筛选区新增关键词输入框，位置放在类型/状态筛选之前，交互对齐现有 `Texts.vue` 的模式：

- 使用现有 `Input` 组件
- `clearable`
- 支持回车触发搜索
- 点击“搜索”按钮也会触发

前端请求时把 `filters.q` 传给 `api.listShares`。

### 4. 二次确认交互

复用项目内已有模式：在页面内使用一个 `Modal` 统一承载确认，不新增全局 confirm composable。

#### 4.1 关闭分享

点击“关闭分享”后不立即执行，而是先弹出确认框：

- 标题：关闭分享
- 内容：明确包含分享类型和资源名称
- 确认按钮：危险态

确认后按类型调用：

- `api.deleteFileShare`
- `api.deleteTextShare`
- `api.deleteTextOneTimeShare`

#### 4.2 重新生成一次性分享

点击“重新生成”后先弹出确认框：

- 标题：重新生成一次性分享
- 内容：明确提示旧链接会失效
- 确认按钮：默认主操作态即可

确认后再调用 `api.createTextOneTimeShare`。

### 5. 状态管理建议

`Shares.vue` 中新增一个统一的待确认动作状态，例如：

- `pendingConfirmAction.kind`
- `pendingConfirmAction.record`

由一个确认弹窗复用两种场景，避免：

- 两个重复 Modal
- 在操作按钮里直接塞业务分支

真正执行逻辑可拆成：

- `performDisableShare`
- `performRegenerateOneTimeShare`

而按钮点击只负责打开确认弹窗。

### 6. 文案与国际化

需补充 `/shares` 页面文案：

- 搜索框 placeholder
- 关闭分享确认标题/正文
- 重新生成确认标题/正文
- 确认按钮文案

保持中英文同时补齐。

### 7. 测试策略

#### 后端

在 `worker/tests/shares-route.test.cjs` 增加：

- 普通用户按资源名搜索
- 普通用户按分享码搜索
- 管理员按 `owner_username` 搜索
- 管理员按 `owner_id` 搜索
- 搜索与现有 `type/status/owner_id` 组合时仍生效

#### 前端

前端当前没有 `/shares` 页面级组件测试基建，本轮不强行引入新测试框架。

最小测试策略：

- 继续保留 `frontend/tests/shares-utils.test.js`
- 如提取纯函数（例如 query params 构造），则补对应单测
- 页面交互通过 `lint + build + 本地联调` 验证

## 风险与控制

### 风险 1：搜索只改前端导致分页错误

**控制：** 明确采用服务端 `q` 搜索。

### 风险 2：确认文案不清晰导致误解

**控制：** 文案必须带资源名；重生成文案必须明确旧链接失效。

### 风险 3：把 owner 搜索下拉混入本轮，导致范围膨胀

**控制：** 本轮明确不做 searchable select，后续单列任务处理。

## 验收标准

- `/shares` 可按关键词搜索，并与分页结果一致
- 普通用户不能通过搜索看到他人分享
- 管理员可通过用户名或 owner_id 快速定位分享
- 关闭分享前必须二次确认
- 重新生成一次性分享前必须二次确认，且旧链接失效提示清晰
- 现有复制、打开、编辑、关闭、重生成能力不回归
