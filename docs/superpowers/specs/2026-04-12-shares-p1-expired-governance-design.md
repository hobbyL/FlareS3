# /shares P1 已过期治理快捷预设设计

**目标**

在不扩大 `/shares` 当前范围的前提下，为站长和普通用户补一条更直接的治理入口：一键切到“已过期分享处理视图”，减少手动组合状态、排序、时间条件的操作成本。

本轮聚焦一个最小能力：

- 顶部新增“已过期治理”快捷按钮

点击后，直接进入已过期分享的治理视图。

## 本轮确认范围

**包含：**

- `/shares` 顶部新增一个快捷治理按钮
- 通过前端预设一次性修改现有筛选状态：
  - `status = expired`
  - `sort_key = expires_at__asc`
  - 清空 `expires_from_date / expires_to_date`
- 点击按钮后立即请求列表
- 保留当前：
  - `q`
  - `type`
  - `owner_id`
- 前端补最小纯函数测试与页面验证

**不包含：**

- 新增后端接口或新的排序字段
- “即将过期治理”第二个快捷预设
- 多个治理模式切换器
- 预设持久化
- 自动勾选当前页、自动批量关闭

## 方案对比

### 方案 A：新增一个“已过期治理”快捷按钮（推荐）

点击后直接把当前列表切到：

- `expired`
- `expires_at__asc`

并清空过期范围。

**优点：**

- 改动最小
- 完全复用现有筛选与排序能力
- 不需要改 worker
- 对站长最直接

**缺点：**

- 只覆盖“已过期治理”，不覆盖“即将过期治理”

### 方案 B：做一个快捷预设下拉

例如：

- 默认视图
- 已过期治理
- 即将过期治理

**优点：**

- 扩展性更好

**缺点：**

- UI 和状态管理都会变复杂
- 当前只有一个高价值预设，收益不足

### 方案 C：新增后端“expired_first”排序

**优点：**

- 语义上更强

**缺点：**

- 需要改后端排序白名单
- 会引入新的接口语义，不符合本轮最小范围

**结论：采用方案 A。**

## 详细设计

### 1. 交互位置

在 `frontend/src/views/Shares.vue` 顶部筛选区、搜索/刷新按钮附近新增一个显式按钮：

- `已过期治理`

它是一个主动治理动作，不是被动筛选项。

### 2. 预设行为

点击按钮时：

- 保留：
  - `q`
  - `type`
  - `owner_id`
- 覆盖：
  - `status = expired`
  - `sort_key = expires_at__asc`
- 清空：
  - `expires_from_date`
  - `expires_to_date`
- 重置：
  - `page = 1`
- 然后立即执行列表请求

### 3. 为什么用 `expires_at__asc`

这是一个**治理场景推断**：

- 对已过期记录，越早过期的记录表示积压越久
- 在治理视角下，积压更久的记录应排在更前

因此本轮默认采用：

- `expired + expires_at__asc`

### 4. 与现有筛选的关系

该快捷预设不是“全量重置”。

它只接管治理强相关字段：

- 状态
- 排序
- 过期范围

而继续保留用户当前的上下文：

- 搜索词
- 类型
- 所属用户

这样管理员可以在“某个 owner 下的已过期分享”之间快速治理，而不必重新选 owner。

### 5. 实现边界

本轮只做前端：

- 不增加 worker 参数
- 不增加新的列表协议
- 不增加新的 sort key

建议把“预设应用逻辑”下沉到 `frontend/src/utils/shares.js`，保持 `Shares.vue` 只负责编排页面事件。

### 6. 测试策略

在 `frontend/tests/shares-utils.test.js` 中补充：

- 一个纯函数，负责生成“已过期治理”预设后的 filters
- 断言它会：
  - 保留 `q/type/owner_id`
  - 强制 `status=expired`
  - 强制 `sort_key=expires_at__asc`
  - 清空过期范围

页面层继续通过：

- `lint`
- `build`

验证不回归。

## 风险与控制

### 风险 1：快捷治理误清空太多上下文

**控制：** 仅清空过期范围，不清空 `q/type/owner_id`。

### 风险 2：快捷治理与现有“搜索后生效”节奏不一致

**控制：** 明确把该按钮定义为“主动治理动作”，点击即查询，避免用户还要二次点搜索。

### 风险 3：未来扩展多个预设时状态变复杂

**控制：** 本轮只实现一个预设，先把逻辑收敛到纯函数，后续再扩展。

## 验收标准

- `/shares` 顶部可一键进入“已过期治理”视图
- 点击后列表立即刷新
- 视图应用：
  - `status = expired`
  - `sort_key = expires_at__asc`
  - 清空过期范围
- 当前 `q/type/owner_id` 保留
- 现有搜索、刷新、批量关闭、排序、过期范围筛选不回归
